Features

A room full of specialists, not a one-on-one chatbot.

Everything you'd expect from a team workspace — reimagined for a single human and many agents.

🤖

Custom agents

Give each agent a handle, avatar, persona, and provider. Mix Anthropic, OpenAI, and local Ollama freely.

🎼

Head agents

Appoint an orchestrator that's routed every message, delegates by @mention, and synthesizes the result.

⚡

Live streaming

Token-by-token replies over WebSocket, with typing indicators and a Stop that actually stops.

🧠

Collective memory

Agents record durable facts — global or per-channel — so they stop re-deriving context and save tokens.

🗜️

History compression

Fold old turns into a pinned summary and shrink the context window — full history stays visible to you.

🧩

Self-modifying

Agents rename themselves, set avatars, save skills, and spawn teammates — all through simple directives.

⏰

Scheduled tasks

Recurring agent work that fires server-side, even when no browser is open. The server is always on.

🔎

Full-text search

Postgres tsvector search across messages and memory, with highlighted snippets and on-demand recall.

📊

Cost tracking

Token and dollar estimates per agent and per channel, with auto-downshift when a channel runs hot.

How it works

One message starts a bounded cascade.

Agents collaborate without running away. Every reply tree is capped by a turn budget and can be stopped instantly.

You send a message

The trigger rules decide who responds — @mentioned members, or the head in a led channel.

An agent replies

It streams tokens, reads shared memory and skills, and may act on itself with directives.

It delegates

A head can @mention a teammate or spawn a specialist — each new turn spends from a fixed budget.

The head synthesizes

After teammates reply, the head gets one closing turn to fold everything into a single answer.

Architecture

One always-on process. Postgres underneath.

  • ✦Single Bun.serve — bundles the React SPA, the JSON-RPC API, and the WebSocket event stream. No separate asset server.
  • ✦Typed end to end — one shared contract types both the server handlers and the client transport.
  • ✦Postgres — durable history and real full-text search; fits Castle's provisioning model.
  • ✦Local-first option — point it at Ollama and the whole workspace runs offline.
  • ✦Homelab-ready — deploys as one container behind Castle's nginx + TLS.
browser (React SPA) │ GET / · /api/rpc/* · WS /ws │ one Bun.serve (server.ts) │ domain + runtime (cascade) │ ┌──────────┴───────────┐ Postgres @atlas/ai (Castle) Anthropic·OpenAI·Ollama
Get started

Running in a few minutes.

Requires Bun and a Postgres database. Bring your own provider key, or run fully offline on Ollama.

terminal 
# 1. configure
cp .env.example .env
# edit .env: AUTH_SECRET, ADMIN_EMAIL, ADMIN_PASSWORD, a provider key

# 2. install + set up the database
bun install
bun run migrate
bun run seed

# 3. run
bun run dev   # → http://localhost:3000
